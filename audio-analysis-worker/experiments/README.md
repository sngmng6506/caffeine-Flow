# 실험 기록

파라미터와 모델 선택의 근거를 남긴다. **기준 문서가 아니라 특정 시점의 측정 기록이다.**

## 다른 문서와 다른 점

- 현재 동작을 반영하도록 갱신하지 않는다. 찍힌 시점 그대로 둔다.
- 결과가 뒤집히면 고치지 말고 새 파일을 추가한다. 옛 파일은 그대로 남는다.
- [docs/README.md](../../docs/README.md) 문서 지도와 [AGENTS.md](../../AGENTS.md) 라우팅 표에 넣지 않는다. 작업 전에 읽는 문서가 아니다.

읽어야 할 때는 두 경우다. 파라미터나 모델을 바꾸려 할 때, 그리고 같은 실험을 다시 하려 할 때.

## 파일 이름

`YYYY-MM-DD-주제.md`

## 반드시 적을 것

| 항목 | 이유 |
| --- | --- |
| 측정 날짜 | 모델 라우팅과 단가는 수시로 바뀐다 |
| 표본 크기와 대상 | 곡 1개로 낸 결론과 50개로 낸 결론은 무게가 다르다 |
| 설정 스냅샷 | `audio-pipeline.json` 커밋 SHA. 어느 설정에서 나온 수치인지 |
| 재현 방법 | 명령 또는 스크립트 |
| **결론에 못 쓴 것** | 없으면 잠정 결과가 정설로 굳는다 |

마지막 항목이 이 문서 형식의 핵심이다.

## 결론 반영

정해진 값은 코드와 담당 문서가 단일 기준이다. 여기에는 근거만 남기고, 결론은
[docs/ROADMAP.md](../../docs/ROADMAP.md)나 해당 계약 문서에 한 줄로 적는다.
