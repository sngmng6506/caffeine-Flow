## 읽어낼 것

**1. 3x10은 곡의 16%만 듣는다.**

186초 곡에서 `0~10s`, `88~98s`, `176~186s` = 30초. 4x30은 `0~30s`, `52~82s`, `104~134s`, `156~186s` = 120초(65%)였다.

재즈 곡은 [2026-09-10 실험](2026-09-10-audio-llm-model-cost.md)에서 4x30으로 **"재즈 피아노로 시작했다가 록/메탈로 폭발"**을 잡아냈다. 오늘 3x10은 8회 중 7회가 록/메탈을 통째로 놓쳤고, 남은 1회도 스쳐 언급했다. 같은 곡·같은 모델이므로 차이는 커버리지다.

**2. 일관성과 정확성은 다르다.**

재즈 곡의 로터리는 8:0으로 완전히 일치했지만, 그 8개가 동의한 서술은 곡에서 가장 특징적인 부분을 뺀 것이다. 판정 안정성만 재면 이 곡은 최고 점수를 받는다.

**3. 판정은 서술의 악기 판독을 그대로 따른다.**

trap 곡의 4:4는 상관이 완벽했다 — 기타로 들은 4회는 전부 accept, 신스로 들은 4회는 전부 reject. 같은 곡 같은 구간인데 실행마다 갈렸다.

```
accept | 깨끗한 톤의 전기 기타가 연주를 이끌고…
reject | 신시사이저 벨 소리 같은 몽환적인 메인 신스가 곡을 이끌고…
```

기준선은 세 곡 모두 5:0이었다. 흔들리는 것은 필터가 아니라 3단 서술이다.

**4. V/A는 장르가 달라도 값이 비슷하다.**

| 곡 | valence / arousal | band() 밴드 |
| --- | ---: | --- |
| K-pop | 0.601 / 0.641 | 중간 · 중간 |
| 재즈→빅밴드 | 0.609 / 0.566 | 중간 · 중간 |
| trap/lo-fi | 0.434 / 0.443 | 중간 · 중간 |

세 곡이 전부 `중간 · 중간`이다. MAEST를 뺀 뒤 남은 유일한 객관 신호가 이 세 곡을 구분하지 못한다.

**5. 균등 배치가 가장 조용한 구간을 고른다.**

재즈 곡의 5초창 RMS를 재고 각 전략이 고르는 구간의 평균 에너지를 비교했다(정규화, 1.0이 최대).

| 전략 | 구간별 에너지 | 평균 |
| --- | --- | ---: |
| 3x10 | 0.19 · 0.35 · 0.62 | **0.39** |
| 3x15 | 0.21 · 0.51 · 0.75 | 0.49 |
| 4x30 | 0.46 · 0.88 · 0.73 · 0.79 | **0.71** |

`plan_segments`는 첫 구간을 0초에, 마지막 구간을 곡 끝에 붙인다. 그래서 **인트로와 아웃트로가 항상 포함**되는데 둘 다 곡을 대표하지 않는다. 이 곡에서는 중간 구간(`88~98s`)마저 하필 브레이크다운(90초에서 E=0.19)에 떨어졌다.

에너지 상위 구간은 `150s(1.00)`, `65s(0.98)`, `120s(0.91)`인데 3x10은 하나도 듣지 않는다. 록/메탈을 놓친 이유가 커버리지 비율만이 아니라 **위치**다.

trap 곡의 3번 구간 서술이 "보컬이 점차 잦아들며, 악기 연주도 마무리되는 분위기"였던 것도 같은 현상이다 — 아웃트로를 들었다.

## 결론에 못 쓴 것

- **정답을 모른다.** trap 곡이 기타인지 신스인지 사람이 듣고 확인하지 않았다. 4:4 중 어느 쪽이 맞는지 모르므로 "모델이 절반 틀렸다"고 말할 수 없다. 재즈 곡의 록/메탈만 2026-09-10 기록이라는 대조가 있어 판단할 수 있었다.
- **3곡, 전부 3분 안팎.** 길이·플랫폼·보컬 유무가 치우쳐 있다. SoundCloud와 10초~10분 경계는 보지 않았다.
- **매장 정책 1개.** 악기를 콕 집는 정책이라 흔들림이 드러나기 쉬운 조건을 골랐다. 평범한 정책("조용한 공부 카페")에서는 2026-09-17 측정에서 16/16 전원 일치였다. 실제 사장님들이 어떤 정책을 쓰는지 모른다.
- **커버리지와 판정의 관계를 재지 않았다.** 3x10이 덜 듣는 것은 확인했지만, 그 때문에 판정이 틀리는지는 별개다. 재즈 곡은 록/메탈을 놓치고도 8:0으로 accept였고 그 판정 자체는 정책과 어긋나지 않는다.
- **구간 수를 되돌렸을 때의 지연을 재지 않았다.** 3x15·4x30의 E2E는 2026-09-17에 쟀지만 그때는 MAEST가 붙어 있었다. 현재 경로에서 다시 재야 한다.

## 재현

```bash
cd audio-analysis-worker
python benchmark_audio_llm.py --platform youtube --track-key '<VIDEO_ID>' \
  --strategies 3x10 --repeats 8 --with-va --va-style number \
  --output ~/bench.json

cd .. && node server/scripts/filter-stability.js --benchmark ~/bench.json \
  --title '<제목>' --artist '<아티스트>' --policy '<매장 정책>' \
  --repeats 5 --output ~/stability.json
```

두 도구 모두 운영 큐·DB에 쓰지 않는다. 실행하면 외부 유료 API 요금이 발생한다.
