# 음악 라벨링

신청곡을 자동 라벨링한 뒤 사람이 그 결과가 곡과 맞는지만 확인하는 관리자 정적 앱이다.

- `/labeling-lab`에서 관리자 sessionStorage 토큰으로 접속한다.
- `/admin/audio-labels`에서 플랫폼·곡별 중복 제거 목록과 서버 집계를 읽는다. AI 필터 OFF·거절 곡과 Spotify 미지원 상태도 포함한다.
- 기본 보기는 자동 분석이 끝난 검토 대상만 보여준다. 대기·실패·미지원 곡은 미검토 전체/전체 보기에서 확인한다.

## 사람이 하는 일

두 가지만 답한다. 택소노미를 고르지 않는다.

1. 아티스트가 맞는지 — 수집한 곡을 플랫폼 검색으로 매칭하므로 엉뚱한 곡을 분석한 것을 잡을 곳이 여기뿐이다.
2. 3단 자유 서술이 곡과 맞는지 — `맞음`·`틀림`·`애매` 중 하나. 셋은 같은 무게로 두어 특정 답으로 몰리지 않게 한다.

판정은 `human_review_status`에 남고 자동 라벨 값 자체는 바뀌지 않는다. `맞음`만 라벨을 사람 라벨(`label_source='human'`)로 승격한다. `틀림`·`애매`는 라벨을 보증하지 않으므로 자동 라벨로 남겨, 재분석과 재정규화가 그 곡을 계속 갱신할 수 있게 한다.

`다음`만 누르면 미검토 상태를 유지한다. 매장 정책 승인·거절 선택은 이 화면에 없다.

## 화면에 보이는 것

- 3단 자유 서술과 분위기·악기·보컬·구성. 사람이 판단하는 유일한 근거다.
- MAEST 상위 스타일의 평균·최댓값과 구간 수, 기본 음향 특징. 원본 버튼으로 전체 구간 JSON과 이력 ID를 조회한다.
- 이상한 곡은 `곡 듣기`로 원래 플랫폼에서 직접 듣는다.
- `AI 음악 서술` 토글은 3단 실행 여부를 서버에 저장한다. 다음 분석부터 적용된다.
- `최신곡 수집`은 고른 소스에서 다음 구간을 훑어 분석 큐를 채운다.

## 규칙

- 분석이나 최종 라벨이 화면 조회 후 바뀌면 409로 저장을 막으며 새로고침 후 다시 검토한다.
- `새로고침`으로 워커 진행 상태를 갱신한다. Spotify는 전체 음원 자동 분석 미지원이다.
- `재시도·재분석`은 실패 또는 완료곡을 현재 모델로 다시 큐에 등록한다. 처리 중인 곡은 재등록하지 않는다.
- `현재 장르 체계 적용`은 저장된 원본으로 재정규화만 실행한다. 기존 사람 라벨은 보호한다.
- 자동 라벨의 기본 사용 목적은 평가다. 사람 확인값은 자동 분석이 덮어쓰지 않는다.

상태·모델 계약은 [아키텍처](../docs/ARCHITECTURE.md), 입력·출력은 [API](../docs/API.md)를 따른다.
