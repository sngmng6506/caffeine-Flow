# 음악 라벨링

전체 카페의 AI 음악 필터 처리 이력을 한 큐로 모아 운영자가 골드 라벨을 기록하는 무빌드 정적 앱이다. 자동 분석이 채운 값을 확인하고 표시된 곡만 직접 듣는 흐름을 전제로 한다. 라벨 값과 수집 정책은 [docs/LLM_FILTER.md](../docs/LLM_FILTER.md#평가-데이터셋)가 기준이다.

## 동작 계약

- 서버가 같은 오리진의 `/labeling-lab`에서 제공한다. 운영자 콘솔의 `sessionStorage` 관리자 토큰만 사용하고, 없거나 만료되면 `/admin`으로 이동한다.
- `GET /api/v1/admin/music-filter-reviews`로 전체·완료·미검수 건수와 50건 단위 큐를 불러온다. `view=ambiguous`는 검수 신호가 붙은 곡을 먼저, 그다음 `min_confidence`가 낮은 순으로 보여준다 — 귀로 확인할 곡이 위로 온다. 정책 검수와 곡 라벨이 있어야 하며, 최신 자동 분석이 있으면 해당 결과도 검수돼야 완료다.
- 저장은 기존 카페 범위 검수 API를 사용한다. 정책 검수는 `music_filter_reviews`, 곡 라벨은 플랫폼 원본 ID 기준 `music_track_annotations`에 upsert한다.
- 곡 라벨은 확인한 아티스트명, 체감 템포, 주요 분위기(최대 2), 사운드 구성, 리듬 특징, 보컬 유형, 선택 장르(최대 2), 메모, 사용 목적을 기록한다. 선택지는 화면에는 한국어로 표시하고 DB에는 안정적인 코드로 저장한다.
- 곡 버전과 메타데이터 충분성은 화면에서 묻지 않는다. 기존 값은 갱신 시 보존하고 새 곡 버전은 `unknown`, 새 메타데이터 충분성은 미확인 `null`로 저장한다.
- 동일한 플랫폼 원본 곡의 기존 특성 라벨은 선택된 상태로 복원하고 저장 시각을 표시한다. 매장 정책 판단은 추천곡별로 새로 선택한다.
- 보컬 유형은 `목소리 없음`, `노래 위주`, `랩·말하기 위주`, `판단 어려움`만 사용한다.
- `판단 어려움`은 같은 항목의 다른 값과 함께 선택하지 않으며, 자유 메모는 정형 선택을 보완할 때만 사용한다.
- 확인한 아티스트의 다른 곡은 운영자가 명시적으로 조회할 때 최신 라벨 최대 3건을 참고 자료로 보여준다. 자동으로 아티스트를 추정하지 않는다.
- 판단 당시 매장 정책 아래에 해당 AI 승인·거절 결과를 바로 표시한다.
- 곡별 최신 Essentia 분석이 있으면 BPM·조성·음향 특징과 자동 추천값을 표시한다.
- **자동 추천값은 폼에 미리 선택된 상태로 뜬다.** 저장은 여전히 사람이 눌러야 하며 자동 저장하지 않는다. 기존 사람 라벨이 있으면 그 값이 우선하고 자동값으로 덮지 않는다.
- 각 항목 옆 배지가 자동으로 채운 칸과 확신도를 보여준다. `확인 필요`는 확신도가 낮아 들어봐야 하는 칸, `직접 선택`은 자동으로 못 채운 칸이다.
- 모델끼리 어긋난 조합(목소리 없음인데 힙합·랩 등)은 분석 패널에 문장으로 표시한다.
- 단축키: `J` 다음 곡, `K` 이전 곡, `O` 곡 듣기, `Ctrl+Enter` 저장. 입력란에 커서가 있으면 가로채지 않는다. 미검수 계열 뷰에서는 저장 후 다음 곡으로 자동 이동한다.
- `확실한 곡 일괄 확정`은 자동 분석이 모든 칸을 채웠고 검수 신호가 없는 곡만 목록에 올린다. 화면 조건은 후보 선별용이고 **자격과 저장 내용은 서버가 저장된 분석에서 다시 판정한다.** 곡 라벨만 저장하고 매장 정책 판단은 남긴다.
- 일괄 확정한 라벨은 `confirmation_mode=bulk`로 저장돼 한 건씩 검수한 라벨과 구분된다. 사실상 모델 출력이므로 같은 모델을 평가할 때 분리해야 한다.
- 제목에 대소문자 구분 없이 `Playlist` 또는 `플리`가 포함된 항목은 큐와 현황 집계에서 제외한다.
- `운영 참고용`과 `평가 전용`을 구분해 저장한다. 현재 라벨은 라이브 추천곡 상태, LLM 입력, 자동수락과 AI 필터 판단을 변경하지 않는다.

서버 실행 후 관리자 콘솔에 로그인하고 `/labeling-lab`에서 접근한다.
