> **함께 갱신할 때:** 후보가 착수·완료·폐기로 상태가 바뀔 때
> **생략 가능한 경우:** 현재 구현의 버그 수정·리팩터링·동작 확인만 할 때

한 번에 **한 항목만** 둔다. 완료한 것은 지운다. 현재 동작은 담당 문서가 기준이다 —
[ARCHITECTURE](ARCHITECTURE.md), [LLM_FILTER](LLM_FILTER.md), [워커 README](../audio-analysis-worker/README.md).

출시 약속이나 일정이 아니다. 착수할 때 GitHub Issue로 옮겨 완료 조건을 확정한다.

## 신청 시점 판단 검증

파이프라인(`EMOTION_LLM`: Valence/Arousal + Audio LLM, 3x10 구간)은 운영에 들어가 있고
1곡 기준 E2E 24.9초다. **검증은 하지 않았다.** 아래를 재기 전까지 이 경로의 판정 품질은
확인되지 않은 상태다.

- **잃은 신호의 영향.** MAEST를 빼면서 필터가 `장르 후보`를, 44.1kHz 특징을 빼면서
  `템포`를 잃었다. 같은 곡의 서로 다른 서술로 판정이 갈리는지는
  `server/scripts/filter-stability.js`가 잰다.
- **V/A 변별력.** 남은 객관 신호가 V/A뿐인데, 과거 실측에서 21곡(전부 K-pop) 중
  valence·arousal 모두 70% 가까이가 중간 구간이었다. 표본이 치우친 것인지 모델 한계인지
  아직 구분하지 못했다.
- **표본.** 지금 근거는 K-pop 1곡이다. 장르·길이·보컬 유무가 다른 곡으로 지연·실패율과
  판정 분포를 다시 본다. 성공한 소수 호출의 분위수로 목표 달성을 선언하지 않는다.
- **정답.** 3단 서술이 맞는지는 사람이 들어야 안다. 구간별 서술이 "1·3구간 기타,
  2구간 배경 신스"처럼 확인 가능한 주장을 내놓으므로 그 구간만 들으면 된다.
- **타임아웃.** 3단 API 왕복에서 55초·75초 이상치를 관측했다. 사용자가 기다리는
  경로인데 현재 타임아웃은 180초이고 폴백 정책이 없다.

측정 도구(`audio-analysis-worker/benchmark_audio_llm.py`,
`server/scripts/filter-stability.js`)는 운영 큐·DB에 쓰지 않지만 **실행하면 외부 유료 API
요금이 발생한다.** 검증 전에는 기존 fail-closed와 DB 보존 계약을 바꾸지 않는다.
