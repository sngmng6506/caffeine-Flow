# 로드맵

> **AI가 읽을 때:** 아직 구현되지 않은 기능을 검토하거나 설계 후보·우선순위를 논의할 때
> **함께 갱신할 때:** 새 개선 후보를 기록하거나 구현 완료·폐기로 후보 상태가 달라질 때
> **생략 가능한 경우:** 현재 구현의 버그 수정·리팩터링·동작 확인만 수행할 때

이 문서는 아직 구현되지 않은 개선 후보를 모은다. 현재 동작은 [ARCHITECTURE.md](ARCHITECTURE.md), AI 음악 필터는 [LLM_FILTER.md](LLM_FILTER.md)가 기준이다.

> 이 목록은 출시 약속이나 일정이 아니다. 실제 착수 항목은 GitHub Issue로 옮겨 범위와 완료 조건을 확정한다.

## 재생 안정성

### 플랫폼 어댑터 분리

`owner/electron/main.js`의 창 관리와 플랫폼별 재생 로직을 분리한다.

완료 조건:

- YouTube·Spotify·SoundCloud별 모듈 경계
- 기존 overlay/takeover 동작 유지
- 플랫폼 변경 시 영향 범위가 해당 어댑터로 제한
- 수동 회귀 체크리스트 마련

### 재생 관측성

재생 시작·실패·종료·BGM 복귀 이벤트를 구조화해 운영 장애를 추적한다.

완료 조건:

- 오류 유형과 플랫폼 기록
- 토큰·개인정보를 제외한 로그
- 반복 실패율 확인 가능

## AI 음악 필터

### 평가 데이터셋

수동 라벨링한 곡으로 필터 품질을 측정한다.

예시 필드:

```text
song_title
artist
cafe_policy
expected_decision
reason
```

지표 후보:

```text
accuracy
false_accept
false_reject
```

### 프롬프트 버전 관리

판단 당시 정책을 재현할 수 있도록 버전 또는 snapshot을 저장한다.

검토 필드:

```text
filter_prompt_version
filter_prompt_snapshot
```

### 판단 캐시

동일 카페·곡·정책의 반복 호출 비용을 줄인다.

캐시 키 후보:

```text
cafe_id + video_id + prompt_hash + model
```

정책 변경과 모델 변경 시 캐시가 자동 무효화되어야 한다.

### 거절 사유 요약

누적된 `filter_reason`을 운영자가 이해하기 쉬운 범주로 요약한다. 원본 사유는 감사 로그로 보존한다.

## 제품 운영

### 관리자 조치 이력

카페 정지·해제·삭제 작업의 운영자, 시각, 사유를 기록한다.

### 장애 복구 절차

DB·Railway·Electron 릴리스 문제에 대한 짧은 운영 플레이북을 작성한다.

### 현장 검증

실제 카페에서 다음을 측정한다.

- 신청 완료율
- 재생 성공률
- 자동 거절률과 오거절 사례
- 사장님 수동 개입 횟수
- 플랫폼별 장애 빈도
