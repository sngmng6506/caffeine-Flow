> **생략 가능한 경우:** 현재 구현의 버그 수정·리팩터링·동작 확인만 수행할 때

## AI 음악 필터

### 수동 곡 라벨 기반 판단 입력

운영자가 확인한 곡 라벨을 충분히 모은 뒤, LLM 판단 전에 같은 플랫폼 원본 곡의 `operational` 라벨을 조회해 프롬프트 참고 데이터로 추가한다. 현재 곡의 라벨이 없을 때만 아티스트명을 정규화해 같은 아티스트의 다른 곡 라벨을 보조 참고로 조회한다.

```text
손님 신청 → 기본 플랫폼 메타데이터 확인
→ (platform, track_key)로 operational 라벨 조회
→ exact 라벨이 있으면 라벨 + 기본 메타데이터로 판단
→ 없으면 아티스트명을 정규화해 artist_key가 정확히 일치하는 참고곡 최대 3건 조회
→ 참고곡도 없으면 기본 메타데이터만으로 기존처럼 판단
```

정규화는 수동 라벨 저장에 쓰는 `normalizeArtistKey`를 재사용한다. NFKC 정규화, 소문자 변환, `- Topic`·`VEVO` 접미사 제거, 연속 공백 정리만 적용하고 유사 문자열 검색이나 자동 동일인 추정은 하지 않는다.

완료 조건:

- `evaluation` 라벨이 라이브 입력에서 제외됨
- exact 라벨은 플랫폼과 원본 곡 식별자가 정확히 일치할 때만 사용함
- 동일 아티스트 참고곡은 exact 라벨이 없을 때만, 정확히 일치하는 `artist_key`로, 최대 3건을 확정 정보가 아닌 참고 사례로 전달함
- 라벨이 없거나 조회에 실패하면 기본 메타데이터만으로 안전하게 판단함
- 사용한 라벨 ID·출처·스키마 버전을 감사 데이터로 추적함
- 기존 골드 라벨 비교에서 false accept가 악화되지 않음

### 권리 확인 오디오 기반 자동 분위기 라벨

평가 대상 곡이 충분히 쌓이면 권리가 확인된 오디오만 별도 작업 큐에서 분석한다. 원본 음원은 보관하지 않고 Essentia로 추출한 음향 특징·임베딩과 Valence/Arousal 회귀 결과만 저장한다. 외부 플랫폼 링크는 곡 식별과 메타데이터 조회에만 쓰며, 링크 등록을 다운로드·분석 권한으로 간주하지 않는다.

```text
관리자 평가 대상 등록 → 플랫폼 원본 곡 식별자로 중복 확인
→ 업로드 또는 명시적으로 허용된 소스인지 권리·출처 확인
→ 백그라운드 워커가 오디오를 임시 파일로 확보
→ Essentia로 BPM·음향 특징·분류 확률·임베딩 추출
→ 전용 모델로 Valence/Arousal 연속값과 신뢰도 추론
→ 신뢰도가 낮거나 경계에 가까운 곡은 수동 검수
→ 특징값·모델 버전·출처·검수 상태만 저장하고 임시 오디오 즉시 삭제
```

자동 분석 결과는 사람이 확인한 exact 라벨을 덮어쓰지 않는다. 라이브 판단 입력 우선순위는 `exact 수동 라벨 → exact 자동 분석값 → 동일 아티스트 수동 참고곡 → 기본 메타데이터`이며 자동값과 수동 보정값은 별도로 추적한다.

완료 조건:

- 권리·출처가 확인되지 않은 음원을 서버에서 추출하거나 장기 보관하지 않음
- 웹 요청과 분리된 작업 큐·워커가 재시도 가능한 상태로 분석함
- `(platform, track_key, model_name, model_version)` 기준으로 중복 분석을 방지함
- Valence/Arousal, 신뢰도, 주요 음향 특징, 분석 시각과 모델 버전을 함께 저장함
- 자동값과 수동 검수·보정값을 구분하고 최종 사용 출처를 감사 데이터로 추적함
- 분석 실패 시 기존 경로로 안전하게 fallback함
- 운영 전 Essentia와 사용 모델의 상업용 라이선스를 확인함
- 골드 라벨과 비교해 허용 오차·신뢰도 기준을 정하고 false accept가 악화되지 않음
