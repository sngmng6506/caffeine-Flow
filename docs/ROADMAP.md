> **생략 가능한 경우:** 현재 구현의 버그 수정·리팩터링·동작 확인만 수행할 때

## AI 음악 필터

### Audio LLM 단독 심사 — 검토 중

곡이 들어온 뒤 사전 분석 DB 없이 오디오만으로 매장 적합성을 판단하는 후보다. **20–30초는 사용 가능성 검토 목표이며 달성한 성능이 아니다.** 현재 `main`의 비동기 다중 모델 분석·저장·신청 필터는 그대로다.

`experiment/audio-llm-latency`의 `benchmark_audio_llm.py`(`e632160` 기준)는 별도 브랜치의 서술 지연 실험이다. 매장 정책이나 승인·거절을 평가하지 않는다. 한 번 받은 음원을 재사용하므로 다운로드+서술 합계는 추정치이며, 큐 대기·신청 처리·최종 심사·저장 시간은 제외한다. 이 수치를 서비스 응답시간으로 읽지 않는다.

판단에 필요한 평가:

- 다양한 길이·플랫폼·구간 설정으로 요청부터 최종 판단까지 지연과 실패율을 측정한다. 성공한 소수 호출의 분위수만으로 목표 달성을 선언하지 않는다.
- 매장 정책별 사람 판정과 대조해 오승인·오거절, 곡당 비용을 비교한다.
- 타임아웃·재시도·저장 범위는 결과를 보고 별도로 결정한다. 검증 전에 기존 fail-closed나 DB 보존 계약을 바꾸지 않는다.

### 수동 곡 라벨 기반 판단 입력

사람이 확인한 `operational` 라벨을 라이브 입력에 쓰는 후보다. 현재는 연결하지 않는다. 곡이 정확히 일치할 때 우선 사용하고, 없을 때만 `normalizeArtistKey`로 같은 아티스트의 참고곡을 제한적으로 조회한다. 아티스트 일치를 곡 특성의 정답으로 승격하지 않는다.

완료 조건:

- `evaluation` 라벨 제외, 플랫폼·원본 곡 식별자 exact 일치, 아티스트 참고 최대 3건
- 조회 실패·라벨 부재 시 기존 입력 유지, 사용한 라벨 ID·출처·스키마 버전 추적
- 매장별 골드 라벨 비교에서 false accept가 악화되지 않음. 다른 매장의 승인·거절은 복사하지 않음

### 자동 분위기 모델과 라이브 판단 확장

저장된 자동 분석의 라이브 입력 연결은 구현돼 있다. 남은 것은 품질 검증이다.

- 분석 포함·미포함 판단을 같은 골드 라벨로 비교하고 false accept를 확인한다.
- Valence/Arousal의 장르별 변별력과 MAEST 스타일 선택 규칙을 평가한다. 소수 표본의 결과·미보정 점수를 일반화하지 않는다.

### Audio LLM 비교 평가

호출·서술 저장·Lab 프롬프트 편집은 구현돼 있다. 과거 모델 비교는 [날짜별 실험 기록](../audio-analysis-worker/experiments/)이며 현재 가격·속도·품질의 보장이 아니다.

- 장르·길이·보컬 유무가 다양한 곡에서 모델·샘플 구간별 서술 품질, 검수 부담, 지연·비용을 비교한다.
- MAEST 결과·임베딩·택소노미를 Audio LLM 입력에 넣지 않는다. 독립된 두 원본을 최종 판단에 활용하는 효과를 평가한다.
- 전체 호출과 선택 호출은 평가 후 결정한다. 미구현 `SELECTIVE` 모드를 현재 계약에 선반영하지 않는다.

### MAEST 장르 캘리브레이션

임계값·매핑은 `server/src/constants/music-taxonomy.json`이 기준이며 아직 미보정이다. 장르별 검증 표본을 확보해 PR-AUC·macro-F1과 임계값을 평가하고, 임계값 선정용 자료와 최종 평가 자료를 분리한다. 전체 서술에 대한 맞음·틀림만으로 개별 장르의 정답을 확정하지 않는다.

## 최신곡 수집

한국 한정 SoundCloud 인기 차트는 보류다. 2026-09-11 당시 확인한 차트 경로는 실패했지만, 이를 모든 SoundCloud 수집이 불가능하다는 뜻으로 확대하지 않는다. 현재 장르별 수집은 [워커 README](../audio-analysis-worker/README.md#최신곡-수집)를 따른다.

재검토 시 실제 응답·지역 범위를 확인한다. yt-dlp의 `only_matching` 테스트는 URL 매칭만 검증하므로 추출 성공의 근거로 쓰지 않는다.
