# 문서 작성 원칙

## 기본 원칙

1. 한 사실은 한 문서에서만 자세히 설명한다.
2. 다른 문서에서는 한 문장 요약과 링크만 제공한다.
3. 현재 구현과 미래 계획을 분리한다.
4. 코드가 단일 기준인 세부 값은 문서에 과도하게 복사하지 않는다.
5. 문서는 독자와 질문 하나에 답하도록 유지한다.

## 문서 선택

- 제품 소개: `README.md`
- 시스템 구조: `ARCHITECTURE.md`
- Electron 재생: `PLAYBACK.md`
- API 경로: `API.md`
- 개발·배포: `DEVELOPMENT.md`
- AI 음악 필터: `LLM_FILTER.md`
- 변경 금지 계약: `AI_CHANGE_GUARDRAILS.md`
- 미구현 계획: `ROADMAP.md`

## 피해야 할 패턴

- API 문서에 긴 설계 배경 작성
- 기능 문서마다 환경변수 목록 반복
- 가드레일에 기능 설명 복사
- 구현되지 않은 API나 테이블을 현재 문서에 기재
- 같은 상태표를 여러 문서에 중복 작성
- 커밋에서 코드 변경과 대규모 문서 재구성을 함께 처리

## 문서 변경 체크

- [ ] 이 정보의 단일 기준 문서가 어디인지 정했다.
- [ ] 기존 문서의 중복 설명을 제거했다.
- [ ] 현재 구현인지 계획인지 명확하다.
- [ ] 링크와 제목 anchor가 유효하다.
- [ ] API·가드레일 CI가 확인하는 문자열을 유지했다.
