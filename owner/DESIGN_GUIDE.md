# Owner Design Guide

> **AI가 읽을 때:** `owner/src`의 레이아웃, 색상, 타이포그래피, 컴포넌트와 상호작용을 추가하거나 바꿀 때
> **함께 갱신할 때:** 사장님 화면의 디자인 방향, 공통 컴포넌트, 버튼 위계, 반응형 기준을 변경할 때
> **생략 가능한 경우:** 화면 결과가 바뀌지 않는 서버·DB 작업과 Electron 내부 수정

사장님 화면의 시각·상호작용 계약이다. 사용자 문구는 [WRITING_GUIDE.md](./WRITING_GUIDE.md)를 따른다. 기존 인라인 스타일은 컴포넌트 단위로 점진 정리하며 화면 검증 없이 전체 스타일을 한 번에 치환하지 않는다.

## 디자인 방향: Calm Operations

영업 중 빠르게 상태를 확인하고 음악을 관리하는 데스크톱 운영 도구다. 쉽고 안정적인 위계를 쓰되 좁은 좌측 패널에서도 필요한 정보가 한눈에 들어오도록 밀도를 유지한다. 핵심은 **꾸미는 것보다 판단 시간을 줄이는 것**이다.

- 명확한 제목, 단일 핵심 행동, 차분한 중립색, 이해하기 쉬운 피드백을 쓴다.
- 데스크톱 운영 도구에 맞는 정보 밀도, 행 중심 설정, 빠른 탐색 구조를 쓴다.
- 특정 서비스의 로고·고유 색상·화면 배치를 복제하지 않는다.
- 손님 화면의 Cyber Queue 컬러와 장식을 가져오지 않는다.
- 화면은 조용하게 유지하고 재생·오류·위험 상태에만 강조를 쓴다.

## 경험 원칙

- **영업 중 행동을 우선한다.** 신청곡 확인·수락·재생 상태처럼 자주 쓰는 기능을 먼저 보여주고, 계정 관리·QR 변경·로그인 복구는 설정이나 접이식 영역에 둔다.
- **한 영역에 하나의 주요 행동.** 같은 카드나 행에서 Primary 버튼을 여러 개 쓰지 않는다.
- **상태와 행동을 구분한다.** `재생 중`처럼 조작할 수 없는 정보는 상태로만 표시한다. 신청 접수와 AI 필터처럼 자주 바꾸는 이진 설정은 상태형 토글 버튼을 쓰되 현재 상태를 문구·점·옅은 배경으로 함께 표현하고 `aria-pressed`를 제공한다.
- **예외 기능은 기본 화면에서 숨긴다.** 쿠키 초기화, 개발자 도구, 강제 복구는 `문제 해결`·`개발자 기능` 같은 접이식 영역에 둔다.
- **좁은 좌측 패널을 기준으로 한다.** 넓은 웹 페이지의 축소본이 아니라 420~720px에서 자연스럽게 재배치되는 구조로 설계한다. 오른쪽 음악 화면을 넓힐 때도 왼쪽에 48px 상태 레일을 남긴다.

## 정보 구조

기본 내비게이션은 세 영역이다.

1. `신청 목록`: 기본 BGM, 재생 중, 대기 곡, 새 신청
2. `이력`: 처리된 신청곡의 최신 기록
3. `설정`: 운영 → 매장 정보 → 음악 서비스 → 계정 및 도움말 → 문제 해결·개발자 기능

`손님 신청 플랫폼`(손님이 신청할 수 있는 범위)과 `음악 서비스 바로가기`(오른쪽 BGM 화면과 로그인 진입점)를 혼동하지 않는다. 관련 기능을 합칠 때도 목적이 다른 컨트롤은 제목과 설명으로 분리한다.

## 색상

| 역할 | 권장값 | 용도 |
| --- | ---: | --- |
| Canvas | `#F5F6F8` | 앱 기본 배경 |
| Surface | `#FFFFFF` | 콘텐츠와 설정 면 |
| Surface subtle | `#F2F4F6` | 보조 영역, 빈 상태 |
| Text strong | `#191F28` | 제목, 핵심 값 |
| Text | `#333D4B` | 기본 본문 |
| Text muted | `#6B7684` | 설명, 보조 정보 |
| Text disabled | `#AAB2BD` | 비활성 정보 |
| Stroke | `#E5E8EB` | 구분선, 입력 테두리 |
| Primary / hover | `#3182F6` / `#1B64DA` | 주요 행동, focus |
| Success | `#00A878` | 정상 완료, 연결됨 |
| Warning | `#F59F00` | 확인이 필요한 상태 |
| Danger | `#E42939` | 삭제, 실패, 중단 위험 |

- 새 색상을 역할 없이 추가하지 않는다.
- 플랫폼 공식 색상은 작은 로고·점·배지에만 쓰고 버튼이나 카드 전체 배경으로 확장하지 않는다.
- 색상만으로 상태를 전달하지 않고 문구나 아이콘을 함께 쓴다.
- 장식용 그라데이션, glow, 강한 그림자를 쓰지 않는다.

## 타이포그래피

기본 글꼴은 시스템 한글 UI 폰트다.

| 역할 | 크기 | 두께 | 줄높이 |
| --- | ---: | ---: | ---: |
| Page title | 20~22px | 700 | 1.35 |
| Section title | 15~17px | 700 | 1.4 |
| Item title | 14px | 600~700 | 1.45 |
| Body | 13~14px | 400 | 1.5 |
| Caption | 11~12px | 400~500 | 1.45 |
| Key metric | 24~28px | 700 | 1.2 |

- 한 화면에서 4단계 이상의 글자 위계를 만들지 않고, 제목을 모두 굵게 만들어 위계를 잃지 않는다.
- 설명은 12px 아래로 줄이지 않는다.
- 긴 곡 제목은 최대 두 줄, 목록에서는 한 줄 말줄임이 기본이다.

## 간격·크기·radius

기본 간격 단계는 `4 / 8 / 12 / 16 / 20 / 24 / 32px`다.

| 역할 | 기준 |
| --- | ---: |
| 같은 행 내부 | 8px |
| 같은 그룹 내부 | 12~16px |
| 섹션 사이 | 20~24px |
| 화면 좌우 여백 | 16~20px |
| 기본 컨트롤 높이 | 40px |
| 중요한 컨트롤 높이 | 44px |
| 아이콘 버튼 최소 크기 | 40×40px |

- 콘텐츠를 억지로 맞추기 위해 임의 간격을 추가하지 않는다. 좁은 패널에서는 여백을 줄이되 컨트롤 높이와 클릭 영역은 유지한다.
- radius는 버튼·입력 8~10px, 카드·details 10~12px, modal 14~16px, 짧은 상태 pill만 `999px`을 쓴다.
- 일반 카드에는 그림자를 쓰지 않고 흰색 surface·얇은 stroke·간격으로 구분한다. 모달이나 업데이트 알림처럼 실제 레이어 관계가 있을 때만 약한 그림자를 허용한다.
- 카드 안에 다시 외곽선 카드를 반복하지 않는다. 같은 맥락의 항목은 하나의 surface 안에서 행과 구분선으로 연결한다.

## 화면별 레이아웃

### 헤더

- 카페명과 영업 중 자주 확인하는 상태만 노출한다.
- 신청 접수와 AI 필터 같은 핵심 토글은 현재 상태를 버튼 안에 표시하고 패널 접기 버튼과 함께 일관된 위치에 둔다.
- 접힌 상태 레일에는 두 상태를 읽기 전용으로 표시한다. 켜짐은 신청 접수에 Success, AI 필터에 Primary를 쓰고 꺼짐은 중립 회색이다. 정상적으로 꺼진 상태에 Danger를 쓰지 않는다. 빨간색은 실제 오류에만 쓴다.
- URL, 카페명 수정, 로그아웃처럼 드문 행동은 설정으로 옮긴다.
- 손님용 신청곡 안내는 AI 필터 설정에서 읽기 전용 미리보기로 제공한다.

### 신청 목록

권장 위계는 `기본 BGM 상태 → 재생 중 → 대기 곡 → 새 신청`이다.

- 실제 재생 중인 곡 영역은 다른 목록보다 한 단계 강하게 표시한다.
- `수락`처럼 내부 처리 행동보다 `재생 중`처럼 현재 결과를 제목으로 쓴다.
- 대기 곡과 새 신청을 같은 카드 스타일로 반복하지 않고 제목·개수·구분선으로 나눈다.
- 빈 상태는 큰 카드 대신 짧은 안내 한두 줄로 표시한다.
- 드래그 대상과 클릭 버튼이 충돌하지 않도록 hover와 focus 상태를 구분한다.

### 이력

최신 기록을 기본으로 보여주고 날짜·처리 상태·곡 정보를 한 행에서 빠르게 읽게 한다. 필터와 날짜 선택은 목록보다 강하게 보이지 않게 하고, 되돌릴 수 있는 행동과 아닌 행동을 명확히 구분한다.

### 설정

- 대분류는 접이식 섹션을 쓸 수 있고 summary에는 제목과 한 줄 설명만 둔다.
- 펼친 영역은 행 또는 작은 섹션으로 구성하며 카드 중첩을 피한다.
- 즉시 반영되는 설정의 `적용` 버튼은 위치를 고정하고, 변경이 없을 때 비활성화해 레이아웃이 움직이지 않게 한다.
- 복구·초기화·개발자 기능은 마지막에 배치하고 기본적으로 접는다.

### 음악 서비스

- YouTube, YouTube Music, Spotify, SoundCloud를 동일한 행 구조로 표시한다.
- 왼쪽에는 서비스명과 계정 조건, 오른쪽에는 행동을 둔다. `오른쪽 화면에서 열기`가 Primary, `로그인`이 Secondary다.
- 로그인 초기화는 `로그인 문제 해결`에 숨긴다.
- 서비스 자체의 자동재생·요금제·재생 가능 여부를 앱이 보장하는 것처럼 표현하지 않는다.

## 컴포넌트

### 버튼

| 종류 | 형태 | 용도 |
| --- | --- | --- |
| Primary | Primary 배경, 흰색 텍스트 | 저장, 수락, 오른쪽 화면에서 열기 등 영역당 하나뿐인 핵심 행동 |
| Secondary | 흰색 배경, Stroke 테두리, Text 색 | 로그인, 취소, 다시 시도 |
| Tertiary | 투명 또는 옅은 회색 배경 | 수정, 펼치기, 보조 이동 |
| Danger | Danger | 삭제·초기화처럼 데이터나 세션에 영향을 주는 행동의 확인 단계 |

- disabled, loading, hover, pressed, focus-visible 상태를 정의한다.
- 같은 역할의 버튼은 화면마다 색상과 높이를 바꾸지 않는다.
- 아이콘만 있는 버튼은 접근 가능한 이름을 제공한다.
- 행동 결과가 다른 버튼을 같은 시각 위계로 나열하지 않는다.

### 입력과 토글

- 입력에는 항상 라벨 또는 명확한 주변 문맥을 제공하고, focus에 Primary 테두리와 ring을 함께 쓴다.
- 토글 라벨은 켜졌을 때 발생하는 결과를 설명한다.
- 저장이 필요한 선택과 즉시 반영되는 토글을 같은 방식으로 보이게 하지 않는다.

### 상태와 피드백

- 성공·경고·오류는 아이콘·색상·문구를 함께 쓰고 오류에는 다음 행동을 안내한다.
- 결과가 화면에서 즉시 보이면 중복 토스트를 추가하지 않는다.
- 로딩 중에는 해당 컨트롤만 잠그고 관련 없는 화면 전체를 막지 않는다.

## 모션

사장님 화면의 모션은 영업 중 판단을 빠르게 하고 상태 변화를 놓치지 않게 하는 수단이다. 입력 피드백, 상태 변화, 공간적 연결, 갑작스러운 변화 완화 중 목적을 설명할 수 없는 모션은 추가하지 않는다.

- 수락·재생·스킵·탭 이동·운영 toggle처럼 반복하는 행동은 즉시 반응해야 한다. 색상 변화와 100~140ms의 미세한 눌림 피드백만 허용하고 키보드 행동에는 이동 애니메이션을 쓰지 않는다.
- 설정 details·modal·업데이트 알림·오류 toast처럼 가끔 나타나는 요소만 150~220ms의 진입·퇴장 모션을 쓴다.
- 등장·퇴장은 strong ease-out, 화면 안 위치 이동·형태 변화는 strong ease-in-out, hover·색상 변화는 ease, 일정한 진행 표시는 linear를 쓴다. 입력 직후 느리게 출발하는 `ease-in`은 사용하지 않는다.
- 공통 곡선은 token으로 관리한다. 기본 후보는 strong ease-out `cubic-bezier(0.23, 1, 0.32, 1)`, strong ease-in-out `cubic-bezier(0.77, 0, 0.175, 1)`이며 비슷한 값을 화면마다 새로 만들지 않는다.
- 기본적으로 `transform`, `opacity`, 색상만 전환하고 `transition: all`을 사용하지 않는다. `width`, `height`, `margin`, `padding`, `top`, `left`를 지속적으로 움직이지 않는다.
- 버튼 눌림은 `scale(0.97)`을 기본으로 하되 작은 아이콘 버튼·드래그 핸들·밀집된 행에서는 배경·색상 반응만 사용할 수 있다. 등장 요소는 `scale(0)`에서 시작하지 않는다.
- 빠르게 반복하거나 되돌릴 수 있는 toggle·toast·details는 중간 상태에서 자연스럽게 방향을 바꿀 수 있는 CSS transition을 우선한다. 재생 상태는 위치 이동보다 문구·점·배경 변화로 전달한다.
- 큐의 위치 변화는 실제 순서 변경이나 drag 중인 곡처럼 공간 관계를 설명할 때만 사용한다. 목록 전체 진입, 장식용 stagger, bounce, blur, 3D 효과는 쓰지 않는다.
- 패널 접기·펼치기는 오른쪽 BrowserView의 크기·위치 동기화와 입력 응답을 우선하며, 시각 효과 때문에 Electron 레이아웃 갱신을 지연하지 않는다.
- `prefers-reduced-motion: reduce`에서는 위치 이동·scale·반복을 제거하되 상태 이해에 필요한 짧은 opacity·색상 피드백과 완료 안내는 유지할 수 있다.
- hover 기반 이동은 `(hover: hover) and (pointer: fine)` 환경에서만 허용한다.

## 접근성·반응형

- 키보드로 모든 버튼·입력·탭·details를 쓸 수 있어야 하고 focus-visible을 제거하지 않는다.
- 텍스트와 배경은 WCAG AA 대비를 목표로 하며 상태를 색상이나 이모지만으로 표현하지 않는다.
- 420px에서 행동 버튼이 겹치면 정보 아래로 자연스럽게 줄바꿈하고, 720px 이상에서 불필요하게 넓은 카드와 긴 텍스트 줄을 만들지 않는다.
- Electron 오른쪽 BrowserView와 겹치거나 가려지지 않는지 확인한다.

## 변경 절차와 체크리스트

1. 실제 컴포넌트, 상태 상수, Electron 연결 지점을 먼저 읽는다.
2. 한 컴포넌트의 사용자 목표와 주요 행동을 정한다.
3. 기존 동작을 유지하면서 시각 위계만 작은 단위로 변경한다.
4. 문구가 바뀌면 [WRITING_GUIDE.md](./WRITING_GUIDE.md)를 함께 확인한다.
5. 420px, 560px, 720px 폭과 실제 Electron 분할 화면에서 확인한다.
6. 키보드 focus, loading, disabled, error 상태를 확인한다.
7. 반복되는 새 결정이 생기면 이 문서를 갱신한다.

- [ ] 영업 중 가장 자주 쓰는 행동이 먼저 보이는가
- [ ] 한 영역의 Primary 행동이 하나로 명확한가
